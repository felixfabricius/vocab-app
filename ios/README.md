# iOS project

Started on 2026-09-22 with `pnpm exec cap add ios` (Capacitor 8, Swift Package Manager). Built and signed only on
GitHub Actions (`.github/workflows/ios.yml`, `fastlane/`); nothing here runs on Windows except `cap sync`.

Since M6 the Xcode project is **generated by xcodegen from `App/project.yml`** (app target plus the
`ALaLunaWidgets` extension) and is not committed; CI runs `cap copy` → `xcodegen generate` → `cap update`. A
locally generated copy from the template still sits in `App/App.xcodeproj` (git-ignored) so `cap sync` works on
Windows. To change build settings, edit `project.yml`.

- Targets: `App` (`PRODUCT_NAME = ALaLuna`, bundle id `in.fabricius.vocab`) and `ALaLunaWidgets`
  (`in.fabricius.vocab.widgets`, sources in `../Widgets`, WidgetKit extension with lock-screen and home widgets and
  two Controls). Deployment target 26.0, iPhone only, manual signing; the build number is the workflow run number.
- The widgets App ID must exist in the developer portal (no capabilities); match provisions both ids.
- `App/Info.plist`: display name `¡A la luna!`, usage descriptions (camera, photos, microphone, speech), portrait
  only, light status bar, `ITSAppUsesNonExemptEncryption = false`.
- `App/App.entitlements`: iCloud Documents with container `iCloud.in.fabricius.vocab` (M5). `Info.plist` declares the
  container as document-scope public (`NSUbiquitousContainers`), which makes the "A la luna" folder appear in the
  Files app. If the build fails with "profile doesn't support the iCloud capability", run the workflow once with
  `force_match` so match regenerates the profile from the App ID's capabilities.
- `App/Base.lproj/Main.storyboard`: the view controller is `ViewController` (module `ALaLuna`), which registers the in-app
  plugins in `App/Plugins/` (`SpeechPlugin`, `TranslatePlugin`, `CloudFilesPlugin`) from `capacitorDidLoad()`.

New Swift files under `App/` or `../Widgets/` are picked up by xcodegen automatically.

`CapApp-SPM/Package.swift` is rewritten by `cap sync` and lists the plugins by their pnpm store paths, which are
deterministic for a given lockfile; CI regenerates it after `pnpm install`. The CLI derives `.iOS(.v26)` from the
deployment target, which only exists from swift-tools-version 6.2, hence
`experimental.ios.spm.swiftToolsVersion: "6.2"` in `capacitor.config.ts` (first CI run failed on this).
