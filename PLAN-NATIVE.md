# ¡A la luna! — implementation plan for the native phase

Status: revision 1, 2026-09-21. Companion to `SPEC-NATIVE.md` (product decisions, §1 is the decision table) and
`HANDOFF.md` (state of the code). `PLAN.md` describes phase 1 and stays valid for everything not changed here.
§9 is the deferred-items tracker and decisions log the spec refers to.

## 0. Ground rules

- **Order of work** is `SPEC-NATIVE.md` §8, as milestones M1–M7 below. A milestone is done when a TestFlight build
  is on the iPhone 14, its on-device checklist is ticked, the docs are updated, and `main` is clean.
- **CI-led, no Mac.** Every native step is attempted from Windows + GitHub Actions first. Time box per blocked
  item: about six CI builds (one evening). Past that, the item goes to §9.1 with what was tried and its fallback,
  and the milestone continues without it.
- **The repo is public** (`github.com/felixfabricius/vocab-app`), so GitHub-hosted macOS runners cost nothing;
  the 200-minute budget in the spec only applies if the repo goes private. The iOS job still runs only on demand
  and on pushes that touch app code (§6). The remote looked several commits behind local on 2026-09-21: push
  before the first CI run.
- **Web app frozen after M1.** The Cloudflare `deploy` job switches to `workflow_dispatch` once the native build
  is verified; the web `test-build` job keeps running on every push (typecheck, tests, build).
- **Swift is written blind**, so: one small plugin per responsibility, every method rejects with a message and a
  code, and an in-app log panel (M1) makes failures visible without Xcode.
- **Nothing in `src/core/*` learns about Capacitor.** Native code enters through the seams in `ARCHITECTURE.md`;
  `src/native/*` holds the typed plugin facades and `Capacitor.isNativePlatform()` is checked in `src/app/services.ts`
  and a handful of screens, nowhere else.

Rough effort, in evenings: M1 3, M2 2, M3 4, M4 2, M5 3, M6 3 (more if the extension target fights back), M7 3.

## 3. Native bridge design

**Registration.** `ios/App/App/ViewController.swift`:

```swift
import UIKit
import Capacitor

class ViewController: CAPBridgeViewController {
    override open func capacitorDidLoad() {
        bridge?.registerPluginInstance(SpeechPlugin())
        bridge?.registerPluginInstance(TranslatePlugin())
        // CloudFilesPlugin (M5), AudioSessionPlugin (M7)
    }
}
```

`Main.storyboard`: the view controller's `customClass` becomes `ViewController`, `customModule="App"`,
`customModuleProvider="target"` (a one-line XML edit). Each plugin is `@objc(NamePlugin) public class NamePlugin:
CAPPlugin, CAPBridgedPlugin` with `identifier`, `jsName`, and a `pluginMethods` list; every method is `@objc func
name(_ call: CAPPluginCall)` and ends in `call.resolve([...])` or `call.reject(message, code)`.

**Facades.** `src/native/speech.ts` etc. call `registerPlugin<SpeechPlugin>("Speech")` and export typed functions.
Codes are a string union (`"unavailable" | "denied" | "busy" | "notFound" | "cancelled" | "failed"`); facades
convert rejections into `NativeError { code, message }`. On the web, facades throw `NativeUnavailableError`;
callers branch on `isNative()` and keep the web behaviour, so `pnpm dev` and the jsdom smoke test keep working.

**Events.** Plugins emit with `notifyListeners("partial", data)`; facades expose `onPartial(cb): () => void`.

**Threading.** File, iCloud and speech work runs off the main thread; SwiftUI hosting (Translate) on main.

**Seam mapping.**

| Seam (`ARCHITECTURE.md`) | Phase-2 implementation | Milestone |
|---|---|---|
| `EXT: audio` `AudioPlayer` | `NativeTtsPlayer` over the community TTS plugin (own `TtsPlugin` only if M7 needs it) | M1 |
| `EXT: transcriber` `Transcriber` | new streaming `LiveTranscriber`; `NativeLiveTranscriber` over `SpeechPlugin`; Whisper stays the web fallback | M3, M7 |
| `EXT: translate` | `translateOffline()` over `TranslatePlugin`; `translateWithClaude` unchanged as the explicit button | M3 |
| `EXT: storage` | Dexie stays; `cloudSync.ts` drains the existing `outbox` into the iCloud container | M5 |
| `EXT: input` | `InputSource` interface; `RemoteButtonsInput`, `VoiceInput` | M7 |
| `EXT: share` | Not used; imports stay on the Import screen (share extension not requested) | — |

### M3 — Translate in-app, lookups → cards, manual add

First custom Swift. The Xcode project stays the template; `scripts/ios/sync-project.rb` (Ruby `xcodeproj` gem,
bundled with fastlane) runs in CI after `cap sync` and adds `App/ViewController.swift` and `App/Plugins/*.swift` to
the App target's Sources phase if not yet referenced (skip entirely if the template uses synchronized groups,
see M1 B3). The storyboard edit (§3) is committed.

**Swift**

- `SpeechPlugin.swift` (~120 lines). `available()`; `requestPermissions()` (speech + microphone);
  `start({ locale, contextualStrings?, maxSeconds?, taskHint?: "dictation" | "confirmation" })` → `AVAudioEngine`
  input tap into `SFSpeechAudioBufferRecognitionRequest` with `requiresOnDeviceRecognition = true`,
  `shouldReportPartialResults = true`, `contextualStrings`; emits `partial { text, isFinal }`; ends on `isFinal`,
  on `maxSeconds`, or after 1.5 s without new partials once something was heard; `stop()` resolves the final text.
  Codes: `denied`, `unavailable` (no on-device model for the locale), `busy`.
- `TranslatePlugin.swift` (~120 lines). Hosts an invisible `UIHostingController<TranslatorHost>` as a child of the
  bridge view controller. `TranslatorHost` keeps `@State configuration: TranslationSession.Configuration?` and
  `.translationTask(configuration) { session in await coordinator.drain(session) }`; `translate({ text, from, to })`
  enqueues and invalidates the configuration; `status({ from, to })` → `LanguageAvailability().status` mapped to
  `installed | supported | unsupported`; `prepare({ from, to })` calls `session.prepareTranslation()` (Apple's
  download sheet). Requests are serialised. Use `Locale.Language(identifier: "es")` and `"en"` first; try
  `es-CL` only after the plain codes work.

**TypeScript**

- `src/speech/LiveTranscriber.ts`: `{ available(): Promise<boolean>; start(lang: "es" | "en", opts, onPartial): Promise<void>; stop(): Promise<string> }`
  with `NativeLiveTranscriber`; locale from `VARIETY.asrLocale` for Spanish, `en-US` for English.
- Translate screen (`features/translate/`), still two panels: textarea; mic button (native: live recognition
  streaming into the field; web: Whisper as today); "Translate" (default provider `settings.translateProvider`,
  `apple` on native) and a secondary "With Claude" button; result with 🔊 on the Spanish text (input for ES→EN,
  output for EN→ES); "Add as card" removed (lookups flow through the button below; Claude's `draft` is stored on the
  lookup row instead). Last five lookups under each panel, tap to refill. Every translation writes a `lookups` row.
  Settings → Translate: pack status per direction with "Download" (`prepare`), default provider.
- **Create cards from lookups.** `lookupsService.createCardsFromLookups(repo, env, ctx, { signal, onProgress })`:
  1. unconsumed lookups (plus rows from the Shortcuts file when the user picks it; that card stays until M6 and
     feeds the same path with `provider: "shortcuts"`);
  2. one draft per lookup via `draftFromLookup`: Spanish side → lemma (trailing punctuation stripped), English →
     gloss, `isPhrase = words > 1`; sentences become `pos: "phrase"` drafts too (D7); a stored Claude `draft` wins;
  3. `createBatch({ sourceType: "lookups", drafts })`, navigate to the table immediately;
  4. `markLookupsConsumed(ids, batch.id)`;
  5. with a key: `enrichBatchDrafts(repo, env, ctx, batchId, { signal, onProgress })` as a job: open, non-known
     suggestions in chunks of 20 through the existing `enrichEntries` pipeline; `mergeDraft(base, enriched)` keeps
     the given lemma and first gloss and fills gender, article, plural, priority, cefr, regional, note, verb,
     `generatedSentence`; from-sentence children are appended as `fromSentences` suggestions; batch counts updated;
     the table reloads per chunk through `useJob`.
  Import screen: "Create cards from N lookups" card; Today: badge with `countUnconsumedLookups()`. The translate-log
  picker path calls the same function (enrichment automatic on import, spec §1).
- **Manual add** (`ManualAddCard.tsx`, replaces "Single word or phrase"): `text` (required, Spanish or English),
  `other` (optional), `tag` (optional). "Complete with AI" → `draftManual(env, ctx, other ? \`${text} = ${other}\` : text)`
  → batch with tag → table. "Save" without AI requires both fields; `looksSpanish()` (accents, ñ, ¿¡, common
  function words) decides which side is Spanish → minimal draft → table, no enrichment.

**Checklist:** offline translation in airplane mode after downloading packs; dictation streams in the right
language per field; speaker reads Spanish; lookups listed and badge counts; "Create cards from lookups" produces
an enriched table with sentences; Cancel stops the job; manual add with and without AI; Whisper still used on web.

### M7 — Voice review level 1, EarPods buttons

**Swift**

  `maxSeconds: settings.voiceListenSeconds`.

  `TtsPlugin.swift` (~60 lines: `voices`, `speak`, `stop`, respecting the configured session); `NativeTtsPlayer`
  keeps its interface (D3).

**TypeScript**

- `src/input/InputSource.ts`: `interface InputSource { attach(h: InputHandlers): void; detach(): void }`,
  `InputHandlers = { flip(), grade(g: GradeName, mode: ReviewMode), repeatAudio(), skip(), isFlipped(): boolean }`.
- `RemoteButtonsInput`: toggle → flip if not flipped, else Good; next → Again (flipping first); previous →
  `repeatAudio()`. Attached in every native review session, independent of voice.
- `VoiceInput` + `features/review/voiceLoop.ts`, per card: speak front (English gloss, `lang: "en-US"`; the player

  normalised (`sí|si|yes` → Good; `no` → Again; `otra vez|repite|repeat` → speak back again and listen) →
  `grade(g, "voice")`. Silence or no match: speak back once more, listen again; still nothing → `skip()`, which
  buries the card for today (D5). Any touch grade cancels the loop for that card. Active when
  `settings.playback === "handsFree"` (label "Voice review") on native with the screen on.
- `ReviewScreen`: builds `InputHandlers` from `doFlip`, `doGrade`, `doBury`, `speakBack`; `rs.grade` receives the

- Level 2 readiness: the loop depends only on `InputHandlers` and the plugins, not on the DOM; the session is
  already play-and-record. Locked operation is a tracker item (§9.1 T3).

**Checklist:** EarPods single/double/triple click with the screen on, then locked (record the locked result); sí/no

## 8. Risks and fallbacks

| Risk | Signal | Fallback |
|---|---|---|
| CORS from `https://localhost` to `api.anthropic.com` / `api.openai.com` | Claude call fails in M1 with a network error, log shows a CORS message | `plugins.CapacitorHttp.enabled: true` (native HTTP, `fetch` patched; `beta.messages.parse` is non-streaming, so it works) |
| `match` cannot create a distribution certificate with the API key | fastlane error on `match` | New key with the Admin role; last resort: CSR via OpenSSL on Windows, certificate created in the portal, `.p12` built with OpenSSL, `match import` |
| Community TTS plugin lacks the voice or resets the audio session | Francisca missing from the list, or M7 recognition breaks after speaking | Own `TtsPlugin.swift` (D3) |
| `cap sync` complains without an `.xcodeproj` (M6) | CLI error | Run `xcodegen generate` before `cap sync`; if the CLI insists on the template layout, keep the project committed and only regenerate in CI |
| Translation framework rejects the language pair or session lifecycle | `unsupported` status or hangs | Plain `es`/`en`; keep the hosting view alive for the app's lifetime; requests serialised |
| WKWebView JavaScript suspended while locked | EarPods commands arrive natively but JS reacts only on unlock | Queue events in the plugin and deliver on resume; locked operation becomes §9.1 T3 (native loop, level 2) |
| Keyboard-up deep link override breaks on iOS 26 | field focused, no keyboard | Accept one tap; note in §9.1 |
| iCloud container URL is nil | `available()` false on first launch | Retry on the next launch; status in Settings; local data is untouched |
| Hand-edited `pbxproj` breaks the project | `xcodebuild` cannot open the project | Only build settings are edited by hand; files go through the Ruby script; xcodegen from M6 |
| Capacitor 8 + SPM plugin products not linked (issue #8325, closed) | undefined plugin at runtime | Pin the latest 8.x; CocoaPods only as a last resort logged in §9 |
| Storage origin | any later change of `iosScheme`/hostname loses IndexedDB | D2: never change; migrate by backup if ever needed |
